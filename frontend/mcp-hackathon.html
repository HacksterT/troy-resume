VA OIG Recommendations MCP Server

An MCP server that lets an AI assistant answer questions across VA Office of Inspector General reports: which findings recur across facilities, whether a theme is growing, what peer facilities did to fix a problem, and how long similar recommendations take to close. Every finding it returns carries a report number and a link.

The problem

VA OIG publishes every report and recommendation it issues, and its website is good at finding individual documents. It cannot answer questions that span documents. Today those answers take hours of reading PDFs, so much of the cross-facility learning they could support does not happen.

The VA has a culture of continuous improvement. The gap this project addresses is not whether VA closes recommendations. It is whether one facility can learn from the findings issued to the others.

vaoig.gov offers full-text search and filters by report type, topic, office, state, VISN, status, and age. Those tools return lists of documents; the person searching still has to open each report, compare it with others, and count. There is no API or bulk export, and the most actionable content, each facility's response with its target date and corrective action, appears only in the report PDFs.

Who it serves

Facility patient safety and quality staff

Anticipate what an OIG inspection will examine, check whether the facility shares weaknesses peers were cited for, and show leadership that recurring national findings were addressed locally.

VISN and VHA program offices

Spot systemic findings that call for a national fix rather than facility-by-facility correction.

Oversight and accountability staff

Track the age of open recommendations and closure performance by office and topic.

Veterans, VSOs, congressional staff, journalists

Ask in plain language what OIG found at a facility and what was done about it.

Three use cases

1. "Has OIG cited this?"

A patient safety manager describes a problem in plain language and finds out whether OIG has cited it before, and where.

2. Preparing for an inspection

A facility manager gets its own history, what peers were cited for, and what peers committed to do, in one request.

3. Reading a trend honestly

A VISN safety officer checks whether a theme is growing, and gets the limits of what that count can show.

All three, worked in detail against OIG's website: see the use cases page →

Approach

Two parts: a data service that turns OIG's public pages and PDFs into a structured, queryable dataset, and an MCP server that gives AI assistants goal-level tools over that dataset. The MCP Overview covers what the server itself does, its tools, and how it has been evaluated. The Data Source Overview covers how the dataset is built.

Limits

The server is not a replacement for VA's internal tracking of OIG recommendations, which is organized around compliance with each recommendation; it is built for learning across facilities. Recurrence of a finding does not by itself show that facilities fail to learn from one another, because OIG inspects against a standard protocol and will find what it looks for. Statuses change after each refresh, so every answer carries its data date. A closure date appears to record when OIG closed a recommendation after reviewing evidence, so time to closure describes OIG's process as well as the facility's, and the server does not report whether facilities met their target dates.
