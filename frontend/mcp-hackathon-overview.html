MCP Overview

VA OIG Recommendations Assistant

The VA Office of Inspector General (OIG) has published about 4,410 reports. Its website is good at finding a document. It is not built to answer a question that spans many documents, such as "what keeps being cited?" or "what did other facilities commit to do about it?" Today, answering those questions means hours of reading reports and PDFs.

In brief

This project connects an AI assistant to a structured copy of what OIG publishes, currently 4,410 reports, 15,649 recommendations, and 11,264 facility responses drawn from report PDFs. Staff ask a question in plain language and get an answer drawn from across all of them, with a report number and link for every finding. The connector is called an MCP server, which is simply a standard way for an AI assistant to use an outside data source.

It uses only public information from vaoig.gov and no internal VA systems. It is not an official VA or OIG product, and it does not replace VA's own tracking of recommendations.

Where it goes beyond OIG's website

OIG's search is solid, and this project does not try to replace it. If you know what you are looking for, the site's keywords and filters will find it, and every answer here links back to the site. The difference is in what happens after the search.

The tools

The server exposes a short, deliberately small set of goal-level tools. New facts become fields on these tools rather than new tools, and it also publishes reference lists of topics, offices, and facilities, and guided prompts for clients that support them.

ToolWhat it answers
Search findingsRecommendations and corrective actions matching a question in any wording, filtered by topic, office, status, report type, VISN, state, or date
Analyze recommendationsExact counts and measures grouped by year, office, topic, or report type: trends, open counts, time to closure, and aging
Systemic clustersRecurring recommendations across reports, with how common each one is and how long similar findings take to close
Facility profileEverything OIG has reported about one facility, with responses, closure dates, repeat findings, and an estimated next inspection window
Report detailOne report with every recommendation, status, closure date, response, and standards cited
Inspection briefOne facility's preparation in one request: its history and open findings, the most common peer findings, what peers committed to do, and an estimated next window
Dataset statusWhat the data covers, when it was collected, and how it compares with OIG's published totals

Safeguards

  • The server returns structured records; the assistant summarizes them. It does not generate findings.
  • Every finding the server returns carries a report number and link, and every response states when its data was collected.
  • Where data supports more than one interpretation, the server says so.
  • The server describes what OIG found and what facilities reported. It does not rate facilities or individuals.

Evaluation

An AI assistant with no other context answers realistic questions using only the server's tools, scored against gold answers computed from a frozen copy of the data: exact matches on counts and report numbers, lists, tool selection, caveats, and a check that every cited report exists. Traces are logged with Arize Phoenix. On the final build, two Claude models each passed 23 of 24 questions and cited no report that does not exist. The test is small, and its authors wrote the questions. An independent agent's answers, with notes on how they checked out, are in the test bank.
